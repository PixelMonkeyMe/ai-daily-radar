进入 QA（质量保证）模式。

用户输入: $ARGUMENTS

## 前置：读取 Dev 交接清单
从对话上下文或 docs/changes/ 获取：
- 本次改了什么
- 数据库是否变更
- Dev 指定的重点测试路径
- 已知风险

## 第一步：自动化检查（前置条件）
运行 `bash scripts/test.sh`，必须全部通过才继续。

## 第二步：代码逻辑审查（Reviewer 职责合并至此）
以独立视角审查代码变更：
- [ ] 代码是否完整覆盖 PRD 所有验收标准？
- [ ] 是否有遗漏的边界条件？
- [ ] 是否有潜在安全/性能问题？
- [ ] 跨文件修改是否同步？
- [ ] 是否与现有功能冲突？

## 第三步：浏览器测试（通过 Playwright MCP）
**使用 Playwright MCP 控制浏览器，模拟真实用户操作。**
这是 QA 最核心的环节，不可跳过。

**通用核心路径（每次必测，覆盖所有功能模块）：**

*页面渲染：*
- [ ] 首页正常加载，日报卡片、总结卡片完整展示
- [ ] 导航栏链接可点击（历史日报、收藏夹、周期汇总）
- [ ] 历史日报页面正常加载，链接不 404

*登录/登出：*
- [ ] 未登录时，导航栏显示"登录"按钮
- [ ] 点击登录 → 弹出邮箱输入弹窗
- [ ] 输入邮箱 → 发送验证码 → 输入验证码 → 登录成功
- [ ] 登录后导航栏显示邮箱 + "登出"按钮
- [ ] 点击登出 → 回到未登录状态
- [ ] 刷新页面 → 登录状态保持（session 持久化）

*收藏功能：*
- [ ] 未登录 → 点击任何 ☆（条目/总结）→ 弹出登录弹窗
- [ ] 登录后 → 点击 ☆ → 按钮变 ★
- [ ] 点击 ★ → 取消收藏 → 按钮恢复 ☆
- [ ] 跳转收藏夹页面 → 能看到刚收藏的内容
- [ ] 刷新/退出重登 → 收藏数据仍在（云端持久化）

*收藏夹页面：*
- [ ] 分类 tab 正常显示且数量正确
- [ ] 切换分类 tab → 数据正确筛选
- [ ] 搜索框输入关键词 → 结果正确过滤
- [ ] 日期筛选 → 结果正确过滤

*AI 功能：*
- [ ] 今日总结内容完整展示（总览/结论/重点/行业/风险）
- [ ] 时段 AI 分析：选日期 → 点分析 → 结果正常渲染

*PDF 导出：*
- [ ] 导出按钮存在且可点击

**本次改动相关路径（额外必测）：**
- 由 Dev 交接清单中指定
- QA 补充遗漏场景

**测试方法：**
1. 用 Playwright MCP 打开线上/本地页面
2. 模拟点击、输入等操作
3. 检查页面元素状态（按钮文字、弹窗显示、数据列表）
4. 截图记录关键步骤

**如果 Playwright MCP 不可用，降级为：**
1. curl 抓取生成的 HTML，检查关键元素和属性
2. 通过 Supabase REST API 直接验证数据写入/读回
3. 代码逻辑追踪（逐行验证执行路径）
4. 在测试报告中注明"降级测试，建议用户手动验证"

## 第四步：数据流验证（涉及数据库改动时）
- [ ] 通过 API 验证数据能否正确写入（新增字段是否兼容）
- [ ] 通过 API 验证数据能否正确读回（跨页面、刷新后是否持久）
- [ ] 写入失败时是否有降级机制（不能静默丢数据）
- [ ] 新旧数据是否兼容（旧记录不会导致新逻辑报错）

## 第五步：回归测试
评估本次改动是否影响现有功能：
- [ ] 其他页面功能是否正常
- [ ] 登录/登出是否正常
- [ ] 已有收藏数据是否受影响

## 第六步：输出测试报告

```
## 测试报告
### 自动化检查
- test.sh：✅ X/Y 通过

### 代码审查
- 覆盖度：✅ / ❌（说明）
- 边界条件：✅ / ❌（说明）
- 冲突风险：✅ / ❌（说明）

### 浏览器测试（Playwright MCP / 降级方式）
- 路径1：✅ / ❌（验证方式 + 结果）
- 路径2：✅ / ❌
- ...
- 测试方式：Playwright MCP / API 降级 / 代码追踪

### 数据流验证
- 写入：✅ / ❌
- 读回：✅ / ❌
- 降级：✅ / ❌
- 兼容性：✅ / ❌

### 回归测试
- 功能A：✅ / ❌

### 结论
- 总计 X 项通过 / Y 项未通过
- 是否允许推送：是/否
- 是否需要用户手动补充验证：是/否（列出项）
```

## 硬性规则
- **全部通过后才允许进入 Ship 模式**
- 如有未通过项，回到 Dev 模式修复
- **禁止仅凭自动化脚本通过就判定测试通过**
- **禁止未经浏览器测试/API 验证就标记通过**
- 降级测试时必须标注"建议用户手动验证"的具体项
