# AI 日报雷达

每天自动汇聚 GitHub 趋势项目、Hacker News AI 热帖、HuggingFace 热门模型、国内 AI 新闻。

---

## 📜 **项目开发规则（强制执行）**

### **规则 1：Workflow 流程必须严格执行**

所有功能开发必须遵循 **PM→QA→Dev→Fix→Ship** 流程，除非特别说明否则不可跳过：

#### **PM 阶段（需求定义）**
- [ ] 5层追问：连续问5个 Why，找到根本需求
- [ ] 数据流图：明确数据从输入到展示的完整路径
- [ ] 验收标准：明确"完成"的定义（Definition of Done）

#### **QA 阶段（影响评估）**
- [ ] 纵向评估：该功能影响哪些模块？
- [ ] 横向评估：该功能影响哪些页面？哪些相关功能？
- [ ] 状态一致性：涉及多个数据源时（内存/localStorage/云端），是否都会同步更新？
- [ ] 测试场景：列出至少3个测试场景（正常/边界/异常）

#### **Dev 阶段（开发实施）**
- [ ] 代码追踪：修改函数 A 时，追踪所有调用 A 的函数 B/C/D
- [ ] 数据流验证：更新数据后，渲染函数是否能读到最新值？
- [ ] 版本号更新：涉及前端文件时，更新版本号防止缓存

#### **Fix 阶段（修复验证）**
- [ ] 最小闭环测试：功能的核心链路是否能跑通？（如：保存→显示）
- [ ] 状态检查：内存变量、localStorage、云端数据库是否一致？
- [ ] 回归测试：修改是否影响了其他功能？

#### **Ship 阶段（部署上线）**
- [ ] 本地验证：在本地环境完整测试一遍
- [ ] 提交信息：commit message 清晰描述改动内容
- [ ] 部署确认：push 后确认功能在线上可用

---

### **规则 2：数据流必须追踪到终点**

**禁止"只写不读"或"只读不写"的修改：**

- 如果修改了**写入逻辑**（如 updateFavoriteContext），必须验证**读取逻辑**（如 renderFavPage）能否读到新数据
- 如果修改了**数据结构**（如添加 context_note 字段），必须验证所有读写该结构的地方都已更新
- 涉及多个数据源时，必须明确：
  - 内存变量（cache）→ 用于页面渲染
  - localStorage → 用于离线缓存
  - 云端数据库 → 用于跨设备同步
  - **三者必须保持一致**

---

### **规则 3：Bug 修复必须遵循 5-Why 分析**

遇到 Bug 时：
1. 先做 5-Why 分析，找到根本原因
2. 评估影响范围（纵向+横向）
3. 制定修复方案（至少2个选项）
4. 实施修复
5. 验证修复（最小闭环测试）
6. 回归测试（确认没有引入新问题）

**禁止"头痛医头"**：不要只修复表面症状，要找到根本原因。

---

### **规则 4：代码修改必须做影响分析**

修改任何函数前，必须回答：
1. 这个函数被谁调用？
2. 这个函数依赖哪些数据？
3. 修改后会影响哪些功能？
4. 需要同步修改哪些相关文件？

---

### **规则 5：前端修改必须考虑缓存**

- 修改 JS/CSS 文件后，必须更新版本号（如 `fav.js?v=3.3a-2`）
- 版本号更新位置：
  - 主页面（index.html）
  - 相关页面（favorites.html 等）
  - 构建脚本（scripts/build_site.py）

---

### **规则 6：提交前必须自检**

Git commit 前必须确认：
- [ ] 功能在本地测试通过
- [ ] 没有引入新的 console.error
- [ ] 版本号已更新（如涉及前端）
- [ ] commit message 清晰描述改动
- [ ] 没有提交不必要的文件（如 .stignore、BUG 示意图等）

## 🔧 **技术栈**

- **数据抓取**：Python 脚本（scripts/fetch_sources.py）
- **AI 处理**：Qwen 摘要 + Kimi 评分（scripts/summarize.py）
- **网站构建**：Python 静态站点生成（scripts/build_site.py）
- **数据库**：Supabase（PostgreSQL + 身份认证）
- **部署**：GitHub Pages + GitHub Actions

---

## 📂 **项目结构**

```
.
├── scripts/              # Python 脚本
│   ├── fetch_sources.py  # 抓取信息源
│   ├── summarize.py      # AI 摘要和评分
│   └── build_site.py     # 生成静态网站
├── docs/                 # 静态网站文件
│   ├── index.html        # 最新日报
│   ├── favorites.html    # 收藏夹页面
│   └── fav.js            # 收藏夹核心逻辑
├── data/                 # 数据存储
│   └── reports/          # 每日报告 JSON
└── .github/workflows/    # GitHub Actions 配置
    └── daily.yml         # 每日自动运行
```

---

## 🚀 **使用方法**

1. **手动运行**：在 GitHub Actions 页面点击 "Run workflow"
2. **自动运行**：每天北京时间 08:00（UTC 00:00）自动触发
3. **查看报告**：访问 GitHub Pages 网站
