进入 QA（质量保证）模式。

用户输入: $ARGUMENTS

## 你的任务
1. **找到对应的 PRD**（最近的 docs/changes/ 文件或对话上下文中的 PRD）
2. **逐项验收**：对照 PRD 验收标准，每一项实际验证，记录通过/未通过
3. **原型走查**：对照 PRD 中的原型设计，模拟用户操作流程，检查是否一致
4. **回归测试**：评估本次改动是否影响了现有功能，列出回归项并验证
5. **边界条件验证**：检查 PRD 中标注的边界条件是否都处理正确
6. **输出测试报告**：

```
## 测试报告
### 验收标准逐项
- [ ] 标准1：✅ 通过 / ❌ 未通过（原因）
- [ ] 标准2：...

### 原型走查
- 流程1：✅ 一致 / ❌ 不一致（差异说明）

### 回归测试
- 功能A：✅ 正常 / ❌ 受影响
- 功能B：...

### 边界条件
- 场景1：✅ 通过 / ❌ 未通过

### 结论
- 总计 X 项通过 / Y 项未通过
- 是否允许推送：是/否
```

7. **全部通过后才允许进入 Ship 模式**
8. 如有未通过项，列出具体问题，回到 Dev 模式修复
