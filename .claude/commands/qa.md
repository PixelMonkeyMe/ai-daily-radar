进入 QA（质量保证）模式。

用户输入: $ARGUMENTS

## 你的任务

### 第一步：自动化检查（前置条件）
运行 `bash scripts/test.sh`，必须全部通过才继续。

### 第二步：逐项验收
找到对应的 PRD（docs/changes/ 或对话上下文），对照验收标准逐项验证。
**不允许直接打勾——必须说明验证方式和结果。**

### 第三步：手动流程测试（不可跳过）
这是最关键的环节。自动化脚本只能检查"代码写得对不对"，不能检查"功能对不对"。
必须模拟真实用户操作路径，逐条验证：

**通用核心路径（每次必测）：**
- [ ] 未登录状态 → 点击 ☆ → 弹出登录弹窗
- [ ] 登录后 → 点击 ☆ → 按钮变 ★，显示"已收藏"
- [ ] 跳转收藏夹页面 → 能看到刚收藏的内容
- [ ] 退出重新登录 → 收藏数据仍在（云端持久化）
- [ ] 取消收藏 → 按钮恢复 ☆，收藏夹中消失

**本次改动相关路径（根据 PRD 补充）：**
- 由 Dev 在交接时列出需要重点测试的操作路径
- QA 补充遗漏的场景

### 第四步：数据流验证
涉及数据库/API 改动时，必须验证：
- [ ] 数据能否正确写入（新增字段是否兼容）
- [ ] 数据能否正确读回（跨页面、刷新后是否持久）
- [ ] 写入失败时是否有降级机制（不能静默丢数据）
- [ ] 新旧数据是否兼容（旧记录不会导致新逻辑报错）

### 第五步：回归测试
评估本次改动是否影响了现有功能：
- [ ] 其他页面功能是否正常
- [ ] 登录/登出是否正常
- [ ] 已有收藏数据是否受影响

### 第六步：输出测试报告

```
## 测试报告
### 自动化检查
- test.sh：✅ X/Y 通过

### 验收标准逐项（必须写明验证方式）
- [ ] 标准1：✅ 通过（验证方式：xxx） / ❌ 未通过（原因）

### 手动流程测试
- 路径1（未登录→收藏→弹登录）：✅ / ❌
- 路径2（登录→收藏→收藏夹可见）：✅ / ❌
- 路径3（跨页面数据持久化）：✅ / ❌
- ...

### 数据流验证
- 写入：✅ / ❌
- 读回：✅ / ❌
- 降级：✅ / ❌
- 兼容性：✅ / ❌

### 回归测试
- 功能A：✅ 正常 / ❌ 受影响
- 功能B：...

### 结论
- 总计 X 项通过 / Y 项未通过
- 是否允许推送：是/否
```

### 硬性规则
- **全部通过后才允许进入 Ship 模式**
- 如有未通过项，列出具体问题，回到 Dev 模式修复
- **禁止仅凭自动化脚本通过就判定测试通过**
- **禁止未经手动流程测试就标记验收标准为通过**
