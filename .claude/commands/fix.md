进入 Fix（Bug 快速修复）模式。

用户输入: $ARGUMENTS

## 执行步骤
1. **复现问题**：理解用户描述的现象，分析可能的根因
2. **定位根因**：
   - 检查相关代码
   - 查看线上文件是否有语法错误
   - 检查浏览器 Console 报错（如用户提供了）
   - 检查最近的 git 变更记录
3. **分析给用户确认**：说明根因和修复方案，等用户确认
4. **修复**：
   - 修改代码
   - 运行 `bash scripts/test.sh` 全部通过
   - 提交代码
5. **推送 + 线上验证**：
   - git push
   - 等待部署完成
   - 线上冒烟测试（验证 bug 已修复 + 未引入新问题）
6. **用户确认修复**

## 注意
- Bug 修复属于 B 级需求，流程精简：定位→确认→修复→验证
- 如果修复涉及架构改动，升级为 A 级或 S 级，走完整流程
- 修复后必须做回归测试，确保不影响现有功能
- 如果是线上紧急故障，可以先修后补 PRD
